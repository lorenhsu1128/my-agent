# MemPalace 專案完整分析

## 專案概述

**MemPalace** 是一個本地優先（Local-first）的 AI 記憶系統，使用「宮殿記憶法」的概念來組織和檢索對話歷史和文件內容。其核心特色是 **verbatim storage**（逐字存儲），不摘要、不重寫，保留原始內容。

### 核心理念

- **本地優先**：所有資料存儲在本地，無需 API 調用
- **結構化索引**：人物和項目成為「翼（wings）」，主題成為「房間（rooms）」，原始內容存在「抽屜（drawers）」
- **可插拔後端**：預設使用 ChromaDB，但介面可插拔其他向量存儲
- **混合檢索**：結合向量语义相似度 + BM25 關鍵字匹配
- **知識圖譜**：基於 SQLite 的時態實體關係圖

### 2. 混合檢索系統（Hybrid Search）

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                         混合檢索流程                                          │
│                                                                             │
│  用戶查詢："為什麼我們改用 GraphQL？"                                         │
│                                                                             │
│  ┌─────────────────────────────────────────────────────────────────────┐   │
│  │ 第一階段：抽屜直接檢索（The Floor）                                   │   │
│  │  ┌─────────────────────────────────────────────────────────────┐   │   │
│  │  │ 1. 使用查詢向量在 ChromaDB 進行 semantic search              │   │   │
│  │  │    - HNSW 索引加速                                         │   │   │
│  │  │    - cosine 距離相似度                                     │   │   │
│  │  │    - 獲取 top N 抽屜                                        │   │   │
│  │  └─────────────────────────────────────────────────────────────┘   │   │
│  │                                                                     │   │
│  │  ┌─────────────────────────────────────────────────────────────┐   │   │
│  │  │ 2. 使用 closet 索引提升排名                                    │   │   │
│  │  │    - Closet 包含主題、實體指向抽屜                           │   │   │
│  │  │    - 對每個 source_file 取最佳 closet 匹配                    │   │   │
│  │  │    - 排名 boost: [0.40, 0.25, 0.15, 0.08, 0.04]            │   │   │
│  │  └─────────────────────────────────────────────────────────────┘   │   │
│  │                                                                     │   │
│  │  ┌─────────────────────────────────────────────────────────────┐   │   │
│  │  │ 3. 混合重排序（Hybrid Re-ranking）                            │   │   │
│  │  │    - BM25 關鍵字匹配                                         │   │   │
│  │  │    - 向量相似度 = max(0, 1 - cosine_distance)               │   │   │
│  │    final_score = 0.6 × vector_sim + 0.4 × bm25_norm            │   │   │
│  │  └─────────────────────────────────────────────────────────────┘   │   │
│  │                                                                     │   │
│  │  ┌─────────────────────────────────────────────────────────────┐   │   │
│  │  │ 4. 抽屜 grep 富化（Drawer-grep Enrichment）                    │   │   │
│  │  │    - 對 closet-boosted 結果，返回關鍵字最佳 chunk + 鄰居      │   │   │
│  │  │    - 提供上下文而非單一片段                                   │   │   │
│  │  └─────────────────────────────────────────────────────────────┘   │   │
│  └─────────────────────────────────────────────────────────────────────┘   │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

## 數據結構

### 抽屜（Drawer）

```python
# 每個抽屜是文件的 verbatim 片段
{
    "text": "文件內容片段（最多 800 字元）",
    "source_file": "/path/to/file.py",
    "wing": "ai-development",
    "room": "technical-discussion",
    "chunk_index": 42,
    "filed_at": "2026-05-03T10:30:00Z",
    "normalize_version": 2,
    "source_mtime": 1714764600.0
}
```

### Closet（主題索引）

```python
# Closet 包含主題指向和實體信息
# 格式：topic|entities|→drawer_id_a,drawer_id_b,drawer_id_c

topic|entities|→drawer_id
"GraphQL migration|→drawer_1,drawer_2"
"switched to|GraphQL|→drawer_1"
"why did we|switch to|GraphQL|→drawer_2"
```

### 知識圖譜三元組

```python
# SQLite 中的時態三元組
{
    "subject": "Max",
    "predicate": "child_of",
    "object": "Alice",
    "valid_from": "2015-04-01",
    "valid_to": null,  # null = 仍然有效
    "confidence": 1.0,
    "source_closet": "closet_xyz",
    "source_file": "/path/to/conversation.jsonl",
    "source_drawer_id": "drawer_123"
}
```

## 性能與基準測試

### LongMemEval 檢索召回率（R@5）

| 模式 | R@5 | LLM 需求 |
|------|-----|---------|
| Raw（純向量檢索） | **96.6%** | 無 |
| Hybrid v4（混合檢索） | **98.4%** | 無 |
| Hybrid v4 + LLM rerank | ≥99% | 任意模型 |

### 其他基準

| 基準 | 指標 | 分數 |
|------|------|------|
| LoCoMo | R@10 | 60.3%（raw）, 88.9%（hybrid） |
| ConvoMem | 平均召回 | 92.9% |
| MemBench | R@5 | 80.3% |

## 安裝與使用

```bash
# 安裝
pip install mempalace

# 初始化宮殿
mempalace init ~/projects/myapp

# 採礦文件
mempalace mine ~/projects/myapp

# 採礦對話記錄
mempalace mine ~/.claude/projects/ --mode convos

# 搜尋
mempalace search "為什麼我們改用 GraphQL"

# 喚醒上下文
mempalace wake-up
```

## 設計哲學

### 1. Local-First（本地優先）
```
┌──────────────────────────────────────────────────────────┐
│                      本地優先架構                         │
│                                                           │
│  所有資料：本地 SQLite + ChromaDB                         │
│  所有運算：本地 ONNX 嵌入模型                              │
│  所有檢索：本地 HNSW 索引                                  │
│  無 API 調用、無雲端依賴                                   │
└──────────────────────────────────────────────────────────┘
```

### 2. Verbatim Storage（逐字存儲）
```
┌──────────────────────────────────────────────────────────┐
│                      逐字存儲原則                         │
│                                                           │
│  不摘要、不重寫、不提取                                   │
│  保留原始對話、原始代碼、原始文檔                          │
│  檢索時返回 verbatim 內容                                  │
└──────────────────────────────────────────────────────────┘
```

### 3. Pluggable Backend（可插拔後端）
```
┌──────────────────────────────────────────────────────────┐
│                     後端插拔架構                          │
│                                                           │
│  BaseBackend → ChromaBackend（預設）                      │
│             → SQLiteBackend（可擴展）                     │
│             → FaissBackend（可擴展）                     │
│             → 自定義後端                                   │
└──────────────────────────────────────────────────────────┘
```

## 總結

MemPalace 是一個設計優雅、架構清晰的本地記憶系統，其最大亮點在於：

1. **結構化設計**：宮殿→翼→房間→抽屜的層次清晰
2. **混合檢索**：向量 + BM25 的實戰組合，96.6% 召回率無需 LLM
3. **本地優先**：完全離線可用，隱私安全
4. **可插拔架構**：後端介面清晰，易於擴展
5. **實戰驗證**：在多個基準測試中表現優異

這使得 MemPalace 成為 Claude Code、Gemini CLI、本地 LLM 等工具的完美記憶配套。
